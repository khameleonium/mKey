# Модули mKey: как устроены и как добавить новый

Архитектурные решения: [ADR-0012](adr/0012-modular-architecture.md), [ADR-0016](adr/0016-lib-layer-and-archtest.md). Требования: SPEC §4.3.

## Слои кода

| Слой | Где | Кто может импортировать | Что может импортировать сам |
|---|---|---|---|
| Сборка программы | `cmd/mkey`, `internal/app` | — | всё |
| Контракты | `internal/contracts` | все | только `internal/lib/*` |
| Инфраструктура ядра | `internal/registry`, `internal/bus`, `internal/i18n` | все | `contracts`, `lib` |
| Модули | `internal/<id>` (и подпакеты) | только `internal/app` | `contracts`, `registry`, `bus`, `i18n`, `lib`, свои подпакеты |
| Чистые библиотеки | `internal/lib/<name>` | все | только другие `internal/lib/*` |

Правила проверяет тест `internal/archtest` (входит в `go test ./...` и `make lint`).
Тестовые файлы (`_test.go`) не проверяются: в тестах можно собирать модули вместе с фейками.

**Модуль или библиотека?** Если у кода есть жизненный цикл (фоновые горутины, открытые
устройства, подписки) или состояние уровня программы — это модуль. Если это чистые функции
и типы (таблица клавиш, парсер DSL) — библиотека в `internal/lib`.

## Жизненный цикл модуля

```
New() → Init(ctx, host) → Start(ctx) → … работа … → Stop(ctx)
```

- **New** — конструктор без зависимостей и без побочных эффектов.
- **Init** — читает свою секцию конфига (`host.Config().Decode`), регистрирует сервисы
  (`contracts.ProvideService`) и расширения (`host.Extensions().Register`), получает
  чужие сервисы (`contracts.LookupService`). Фоновую работу не запускает.
- **Start** — запускает фоновую работу (горутины), не блокируется надолго.
- **Stop** — останавливает работу и освобождает все ресурсы, включая зажатые виртуальные
  клавиши и захваченные устройства. Вызывается и после неудачного Init/Start, поэтому
  должен выдерживать частично инициализированное состояние.

Ядро вызывает Init у всех модулей по порядку, затем Start по порядку, затем Stop в обратном порядке.

## Обязательные и необязательные модули

- **Обязательный** (`Core: true`): его ошибка в Init/Start останавливает запуск программы.
- **Необязательный**: отключается в `config.yaml` (`modules.<id>.enabled: false`); его ошибка
  или паника записывается в статус модуля (`failed`), остальные модули продолжают работу.

Программа обязана работать при отключении любого необязательного модуля — это проверяет
`internal/app` (тест `TestEachOptionalModuleCanBeDisabled`). Если ваш модуль зависит от
сервиса другого модуля, обрабатывайте `contracts.ErrServiceNotFound` (например, отключайте
свою функцию и сообщайте об этом пользователю), а не падайте.

## Как модули общаются

1. **Сервисы (контракты).** Модуль-поставщик регистрирует реализацию интерфейса из
   `internal/contracts`; потребитель получает её по типу интерфейса:
   ```go
   // В Init поставщика: публикуем реализацию контракта.
   if err := contracts.ProvideService[contracts.OutputSink](host.Services(), m.sink); err != nil {
       return err
   }

   // В Init потребителя: получаем реализацию; её может не быть, если поставщик отключён.
   sink, err := contracts.LookupService[contracts.OutputSink](host.Services())
   ```
   Поставщик должен идти в `internal/app/modules.go` раньше потребителя.
2. **Шина событий.** Для уведомлений «что-то произошло» (устройство подключено, событие
   сработало): `host.Bus().Publish("input.device_added", payload)` и
   `host.Bus().Subscribe("input.*")`. Публикация не блокирует отправителя.
3. **Точки расширения.** Новые типы действий, триггеров, адаптеров и т.п. регистрируются
   в `host.Extensions()` с метаданными (`contracts.ExtensionMeta`), по которым GUI строит
   блоки конструктора.

### Блок конструктора для своего вида

GUI строит блок и его поля только по метаданным (`GET /api/v1/registry`), поэтому новому
виду действия, триггера или условия достаточно правильных метаданных:

- `NameKey` / `DescriptionKey` — i18n-ключи названия и описания (обычно `action.<id>` и
  `action.<id>.description`); `Category` — раздел палитры (`keyboard`, `mouse`, `time`, `logic`,
  `system`, `script` или свой — его название берётся из ключа `category.<имя>`).
- `ParamsSchema` — JSON Schema параметров (`type`, `enum`, `properties`, `required`, `oneOf`,
  `default`, `minimum`). Порядок полей в схеме — порядок полей в блоке. Подписи берутся из
  i18n: `<NameKey>.field.<поле>` (и `.hint` — подсказка), `<NameKey>.field.<поле>.<значение>`
  для значений списка, `<NameKey>.value.<значение>` — если схема сама список,
  `<NameKey>.variant.<номер>` — для вариантов `oneOf`.
- Подсказки для полей: `x-widget` — `key` (клавиша с кнопкой «Нажмите клавишу…»), `keys`
  (сочетание в скобках, `{Ctrl+H}`), `macro` (текст макроса с проверкой), `ms` (миллисекунды),
  `multiline`, `code` (+ `x-lang`: `lua` | `shell`), `event`, `project`, `variable`, `device`,
  `time`, `value`, `actions` / `conditions` (вложенные блоки, как в «Повторять» и «Если»);
  `x-advanced: true` — поле прячется под «Подробнее».
- Виды показываются в порядке регистрации.

Нужного контракта нет — добавьте интерфейс в `internal/contracts` **отдельным коммитом** с
обоснованием. Контракты — публичное обещание плагинам: ломающие изменения только через ADR.

## Как создать модуль

```bash
make new-module NAME=recorder
```

Генератор (`tools/newmodule`) создаёт:

- `internal/recorder/doc.go` — описание пакета (заполните TODO);
- `internal/recorder/module.go` — модуль с `Config`, `New`, `ID`, `Init`, `Start`, `Stop`;
- `internal/recorder/module_test.go` — тест полного жизненного цикла;
- `web/src/features/recorder/index.ts` — папка фичи во фронтенде;
- i18n-ключ `recorder.module.name` во всех каталогах переводов (Go и фронтенд);
- строку `{Module: recorder.New(), Core: false},` и импорт в `internal/app/modules.go`.

После генерации: заполните `doc.go`, переведите `recorder.module.name`, при необходимости
сделайте модуль обязательным (`Core: true`) и переставьте его строку в нужное место списка.

## Чек-лист модуля

- [ ] `doc.go`: назначение, основные типы, какие контракты предоставляет и использует, как расширять.
- [ ] Модуль не импортирует другие модули (`go test ./internal/archtest/` зелёный).
- [ ] Stop освобождает все ресурсы и выдерживает вызов после неудачного Init/Start.
- [ ] Работает (или корректно деградирует) при отключённых модулях-поставщиках.
- [ ] Пользовательские строки — в i18n (ru и en), ключи с префиксом `<id>.`.
- [ ] Код прокомментирован по [правилам](code-style.md).
