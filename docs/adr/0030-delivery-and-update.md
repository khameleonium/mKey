# ADR-0030: Поставка (goreleaser, пакеты) и обновление

- **Статус:** принято (2026-10-02)
- **Связано:** T10.1–T10.3, FR-INST-1, FR-INST-6, D2

## Контекст

mKey поставляется одним статическим файлом (D2, FR-INST-1.1) и пакетами для дистрибутивов
(FR-INST-1.2). Нужны воспроизводимые выпуски для amd64 и arm64, контрольные суммы и подпись,
а также обновление программы без ручной работы (FR-INST-6) — так, чтобы mKey не ходил в сеть
без согласия человека (NFR-8: никакой телеметрии).

## Решение

1. **Сборка выпусков — goreleaser** (инструмент сборки в CI, не зависимость кода): по тегу `v*`
   workflow `release.yml` проверяет код и собирает `mkey` и `mkey-cli` (amd64, arm64), архивы
   `mkey_<версия>_linux_<arch>.tar.gz`, `checksums.txt` (sha256) и пакеты через встроенный nfpm:
   **deb, rpm, apk (Alpine), archlinux**; для AUR — `packaging/aur/PKGBUILD` (`mkey-bin`),
   публикует владелец. Пакет для xbps (Void) nfpm не умеет — на Void подходит архив.
2. **Подпись** — аттестация происхождения сборки GitHub/Sigstore (`actions/attest-build-provenance`)
   для всех файлов выпуска: без хранения ключей, проверка `gh attestation verify`.
3. **Пакеты ничего не меняют в системе молча:** только `/usr/bin/mkey`, ярлык, иконка, документация.
   Правила udev и автозапуск настраивает мастер — с объяснением и согласием, как и при установке
   архивом. Программа, запущенная вне домашней папки, считается установленной в систему: мастер не
   копирует её в `~/.local/bin`, `mkey uninstall` подсказывает удалить пакет менеджером пакетов.
4. **Обновление — модуль `update`** (необязательный):
   - **проверка выключена по умолчанию**; включается в мастере установки, в «Настройках» или
     в config.yaml (`modules.update.check`); при включении mKey раз в сутки спрашивает GitHub
     о последнем выпуске (адрес — только `api.github.com` и файлы выпуска), о новой версии
     сообщает уведомлением один раз. Кнопка «Проверить» и `mkey update --check` работают всегда —
     это явная просьба человека;
   - **установка**: скачать архив своей сборки (полная/консольная, своя архитектура) и
     `checksums.txt`, сверить sha256 (не совпало — ничего не меняется), атомарно заменить
     `~/.local/bin/mkey` (прежний файл остаётся как `mkey.old` до следующего обновления),
     перезапустить демон той же командой (`Lifecycle.Restart` — модули корректно останавливаются,
     клавиши отпускаются, затем процесс заменяется новой программой);
   - **установлено пакетом** или **сборка разработчика** (`dev`) — обновлять сам mKey не будет и
     объяснит почему (пакет обновляет менеджер пакетов).
5. **Миграция настроек с бэкапом:** `config.yaml` и проекты имеют `version`. Новая программа,
   увидев старую версию файла настроек, сначала сохраняет копию `config.yaml.v<N>.bak`, затем
   переводит файл шагами `vN → vN+1` (`internal/lib/config`, `migrations`). Файл новее программы —
   ошибка (откат на старую версию не портит настройки).

## Последствия

- Выпуск — один тег; пакеты и архивы для двух архитектур собираются одинаково.
- mKey ходит в сеть только по явному выбору человека.
- Обновление не оставляет программу «полузаменённой»: проверка суммы до замены, замена
  переименованием, предыдущая версия сохраняется.

## Альтернативы

- **Самодельные скрипты сборки** — больше кода для поддержки; goreleaser даёт архивы, суммы и
  пакеты одним конфигом.
- **Подпись GPG/cosign с ключом** — нужно хранить секретный ключ; аттестация без ключей проще и
  проверяема.
- **Автоматическое обновление без вопроса** — противоречит принципу «ничего не делать молча».
