# ADR-0027: Имена кнопок устройств переносят проекты (вместо отдельных профилей устройств)

- **Статус:** принято (решение владельца, 2026-10-01; заменяет первую версию этого ADR с
  отдельными «профилями устройств»)
- **Связано:** T7.4, FR-DEV-5, FR-DEV-7, FR-PLG-8, ADR-0026

## Контекст

Имена кнопок необычных устройств (ADR-0026) человек даёт сам: переименование, мастер разметки.
Первая версия этого решения добавила отдельную сущность — «профиль устройства» (файл с именами
кнопок модели: встроенные профили, папка профилей, «Сохранить профиль»). Владелец указал, что это
лишнее усложнение: то, что человек понимает под профилем («Китайский геймпад 1» — что нажато и
что при этом делать), в mKey уже есть — это **проект**. Профиль только с именами сам ничего не делает.

## Решение

1. Отдельных профилей устройств нет: встроенные профили, папка профилей, `mkey devices profile`
   и «Сохранить профиль» убраны.
2. **Имена кнопок хранятся в проекте** — раздел `devices` (`lib/devmap.Names`):
   ```yaml
   devices:
     - match: { vid: "0079", pid: "0011", name: "USB Gamepad" }  # модель (name — необязательно)
       name: Геймпад
       buttons: { BTN_TRIGGER: Старт }    # код ядра → имя кнопки
       axes: { ABS_THROTTLE: Газ }
   ```
   Кнопки — кодами ядра, а не номерами `001`: номер зависит от того, у каких кнопок модели нет
   стандартного имени, а код — нет. Проверка — `project.Check` (модель, коды, имена по правилам).
3. **Сохранение проекта в файл** («Проекты» → «Сохранить в файл», `mkey project export`,
   `GET /api/v1/projects/{id}/export`) дописывает в `devices` имена кнопок устройств, которые
   встречаются в проекте (`{Геймпад.Старт}`, `{UnKey001}`); записи других моделей и комментарии
   файла сохраняются. Один файл — и события, и имена кнопок.
4. **Загрузка:** имена из раздела `devices` всех проектов (включённых и выключенных — загруженный
   чужой проект выключен) подставляются подключённому подходящему устройству: при подключении и
   при изменении проектов. Имена человека важнее; каждый проект применяется к устройству один раз
   (отметка `applied` в devices.yaml) — убранное имя не возвращается. Устройство с подходящими
   именами получает авто-ID, даже если по режиму авто-ID не получило бы.
5. Точка расширения `device_profile` остаётся зарезервированной.

## Последствия

- Обмен разметкой — обменом проектами; встроенных разметок нет (их нельзя проверить без
  устройств).
- Имена из проекта появляются, когда устройство подключено; до этого события с `{Геймпад.Старт}`
  сообщают «устройство не найдено».

## Альтернативы

- Отдельные профили устройств (первая версия) — лишняя сущность рядом с проектами.
- Номера кнопок в проекте — ломаются, если у модели другой набор кнопок без имени.
