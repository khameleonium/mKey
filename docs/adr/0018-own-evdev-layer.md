# ADR-0018: Собственная обёртка evdev/uinput вместо go-evdev; зависимости фазы 1

- **Статус:** принято
- **Дата:** 2026-09-30
- **Связано:** SPEC.md §11, D1, D2; T1.1–T1.3, T1.8

## Контекст

SPEC предлагал `github.com/holoplot/go-evdev` для чтения устройств и собственный пакет
для uinput, «если не хватит возможностей». Для mKey нужны: полный набор ioctl evdev
(имя, phys, uniq, id, маски возможностей, параметры осей, свойства, состояние клавиш, grab),
полная настройка uinput (UI_DEV_SETUP, UI_ABS_SETUP, свойства, phys, sysname), чтение с
прерыванием через Close и точная таблица кодов клавиш.

## Решение

1. Пакет `internal/lib/evdev` — своя тонкая обёртка на `golang.org/x/sys/unix` (~600 строк):
   ioctl evdev и uinput, кодирование `struct input_event`, классификация устройств,
   разбор `/proc/bus/input/devices` (список устройств без прав — для диагностики).
   Номера ioctl вычисляются макросами `_IOC` и сверены тестом с эталонными значениями.
2. Коды событий (`KeyA`, `BtnLeft`, …, 779 констант) **генерируются** из
   `linux/input-event-codes.h` командой `tools/gencodes` (`make gencodes`); результат
   `codes_gen.go` хранится в репозитории. Ручной набор таблицы исключён: ошибка в коде —
   это «не та клавиша» у пользователя.
3. Чтение идёт через `os.File` (поллер Go): `Close` прерывает блокирующий `Read`,
   поэтому остановка модуля не зависает. ioctl выполняются через `SyscallConn().Control`,
   чтобы не переводить файл в блокирующий режим.
4. Новые зависимости Go: `golang.org/x/sys` (ioctl, uname, termios) и
   `github.com/fsnotify/fsnotify` (hotplug устройств через inotify на `/dev/input`;
   позже — горячая перезагрузка конфигов, фаза 3).
5. Имена контрактов уточнены при реализации: вместо `contracts.OutputSink` —
   `contracts.VirtualDevices` / `contracts.VirtualDevice` (менеджер и устройство),
   источник ввода — `contracts.InputSource`.

## Последствия

- Поддерживаются только 64-битные архитектуры (amd64, arm64): от этого зависит размер
  `struct input_event` (24 байта). Это соответствует NFR-5.
- Force feedback пока не поддерживается (`ff_effects_max = 0`), появится в фазе 7 (FR-VD-5).

## Альтернативы

- `holoplot/go-evdev` — не покрывает часть нужных ioctl uinput, и всё равно понадобился бы
  собственный пакет; две обёртки над одним интерфейсом хуже одной.
- Прямой inotify через `x/sys` вместо fsnotify — возможно, но fsnotify понадобится для
  конфигов, а его API проще и проверен.
