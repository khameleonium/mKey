# ADR-0042: Самостоятельный файл макроса

- **Статус:** принято (2026-10-08, по просьбе владельца; в плане с 2026-10-07 как «`mkey build`»)
- **Связано:** FR-BUILD-1, ADR-0023 (две сборки), ADR-0028 (устройства в проектах)

## Контекст

Владелец хочет из проекта собирать один исполняемый файл, который работает сам по себе: его можно
передать другому человеку (или продать готовую автоматизацию), и тому не нужно устанавливать и
настраивать mKey.

## Решение

1. **Формат** (`internal/lib/bundle`): `[программа mkey][zip][хвост 24 байта]`. Хвост — метка
   `MKEYBNDL`, версия формата, длина архива. В архиве — `manifest.json` (название, проект, режим,
   событие, когда и какой версией собран, создатель mKey), `project.mkey.yaml` как есть (с
   комментариями), записи `recordings/*.mkrec` и скрипты `scripts/lua/*`, `scripts/shell/*`, на
   которые ссылаются действия `play`, `lua {file}`, `shell {file}`. Пути проверяются при записи и
   чтении (только эти папки, без «..»), размер файла внутри — не больше 256 МБ. Ядро запускает такой
   файл как обычную программу: лишние байты в конце ELF ему не мешают. Внешних зависимостей нет
   (`archive/zip`).
2. **Сборка** — модуль `builder` (`contracts.MacroBuilder`): проверяет проект (`ValidateProject`),
   событие для режима «выполнить и выйти», находит файлы через места модулей (`recordings`,
   `lua_scripts`, `shell_scripts`) и дописывает всё к своей программе (`os.Executable`; из
   собранного файла — с заменой прежнего содержимого). Действия плагинов — ошибка: плагин —
   отдельная программа, её на чужом компьютере может не быть. Запись — во временный файл рядом и
   переименование, права 0755. Папка по умолчанию — место `builds`
   (`~/.local/share/mkey/builds`). API: `POST /projects/{id}/build`, скачивание —
   `GET /builds/{name}` (только из этой папки). CLI: `mkey build <проект> [-o файл] [--once событие]`.
3. **Запуск** (`cmd/mkey/standalone.go`): в начале `main` программа читает свой хвост. Есть
   содержимое и нет аргументов — режим макроса: временная личная папка (`XDG_CONFIG_HOME`,
   `XDG_DATA_HOME`, `XDG_STATE_HOME` — туда; `XDG_RUNTIME_DIR` не меняется: он нужен D-Bus и
   Wayland), модули без `api`, `plugins`, `update`, `builder` (установленный mKey и его сокет не
   затрагиваются), проект включается; режим `events` работает до «Выйти» в меню значка, Ctrl+C или
   конца сеанса, режим `once` выполняет событие и выходит. Нет доступа к `/dev/uinput` — понятное
   уведомление и `--setup-access` (то же, что `mkey doctor --fix`). Свои аргументы: `--info`,
   `--setup-access`, `--help`; остальные — обычные команды mkey (нужно для `privileged` при выдаче
   прав). `MKEY_FAKE_BACKENDS=1` — запуск без настоящих устройств, только для проверок.

## Последствия

- Файл весит столько же, сколько программа mkey (≈15–25 МБ), и работает на той же архитектуре
  процессора, что и собравший его mKey.
- Содержимое не шифруется: `--info` и любой архиватор покажут проект — это не защита авторского
  макроса от чтения.
- Безопасность: такой файл — обычная программа; запускать стоит только файлы из доверенных рук
  (внутри могут быть скрипты bash). Экстренная остановка Esc + Backspace + Enter работает, как в mKey.

## Альтернативы

- Отдельная маленькая «программа-проигрыватель» без модулей — пришлось бы дублировать движок,
  привязки и устройства; отвергнуто (AGENTS §4.1).
- Сжатый самораспаковывающийся архив с установщиком — требует установки и прав администратора на
  чужом компьютере; отвергнуто.
