# ADR-0024: Запись и воспроизведение — формат .mkrec и работа из терминала

- **Статус:** принято
- **Дата:** 2026-09-30
- **Связано:** T6.1, T6.2, T6.5, FR-REC-1…5, D16

## Контекст

Этап 6: запись ввода и её повтор. Владелец просит в первую очередь простые команды терминала
(«записал в игре — повторил одной командой»). SPEC FR-REC-3 задаёт JSON Lines с заголовком.

## Решение

1. **Формат** — простой текст, который удобно править (решение владельца): одна строка — одно
   действие (пакет событий устройства между `SYN_REPORT`): `время устройство действия [@ x y]`;
   действия записаны как в макросах (`^{A}`, `~{Mouse0}`, `move +12 -3`, `wheel -1`, `ev t c v`).
   Заголовок — строки `mkrec 1`, `created`, `device`, `desktop`, `pointer`; конец — `<время> end`.
   Отступление от FR-REC-3 (там — JSON Lines и zstd): JSON неудобно править вручную.
   Автоповторы и `EV_MSC` не пишутся; перемещения мыши склеиваются по 8 мс.
2. **Запись** идёт в демоне (модуль `recorder`, контракт `contracts.Recorder`): события пишутся
   в черновик на диске, последние 2 с держатся в памяти, чтобы вырезать сочетание остановки;
   заголовок с полным списком устройств добавляется при сохранении, файл заменяется целиком
   (переименованием), так что прерванная запись не портит прежнюю с тем же именем.
3. **Старт/стоп** — `mkey rec` (отсчёт, Ctrl+C вырезается), `mkey rec stop`, окно, сочетание
   `Ctrl+Alt+R` из любой программы (без перехвата клавиатуры: сочетание видят и программы).
4. **Воспроизведение** (`contracts.Player`) — пакеты между `SYN_REPORT` отправляются в
   виртуальные клавиатуру и мышь по расписанию от начала прохода (без накопления ошибки);
   проход длится ровно длительность записи (ритм при повторах); перемещения мыши склеиваются
   в окне 4 мс, чтобы 1000-герцовая мышь не упиралась в ограничитель SEC-4. Клавиши, нажатые
   повтором, отпускаются при любой остановке. `mkey stop`, `mkey panic` и экстренная
   остановка прерывают воспроизведение.
5. **Действие `play`** для проектов (блок «Воспроизвести запись», категория `record`).
6. **Калибровка мыши (T6.3, FR-REC-5, решение владельца):** одинаково во всех окружениях —
   перед записью и перед каждым проходом воспроизведения указатель ставится в центр экрана
   виртуальным устройством «mKey Pointer» с абсолютными осями (`VirtualDevices.CenterPointer`;
   середина осей — центр рабочего стола при любом размере). В файле — строка `pointer center`.
   Чтение положения указателя (для KDE — скрипт KWin) исследовано, но не используется: оно
   есть не во всех окружениях.
7. **Защита:** записывается то, что получили программы (`InputEvent.Delivered`), нажатия,
   «съеденные» mKey (`InputEvent.Consumed`), пропускаются; экстренная остановка заканчивает
   запись и вырезает сочетание (всё после последнего момента без нажатых клавиш).

8. **Удобства ручной правки (решение владельца, 2026-10-01):** `#` после пробела (вне кавычек)
   начинает комментарий до конца строки; строка `shift ±секунды` сдвигает время всех строк ниже
   (сдвиги складываются, `end` тоже сдвигается; время меньше нуля — ошибка); при записи перед
   паузой от 1 с вставляется пометка `# ---- пауза N с ----`. Версия формата не меняется
   (`mkrec 1`): файлы, которые пишет программа, содержат только полные строки-комментарии и
   читаются и прежними версиями; `shift` и комментарии после действий добавляет человек.
   Ошибки в файле описываются с номером строки и понятной причиной (`mkrec.Problem`).

## Последствия

- Геймпады и тач пока не воспроизводятся; при включённом ускорении мыши путь курсора может
  немного отличаться (для точности — профиль ускорения «Плоский»).
- Конвертация записи в блоки (T6.4) — позже.

## Альтернативы

- Бинарный формат — меньше, но не читается человеком и скриптами.
- Запись в самом процессе `mkey rec` (без демона) — дублировала бы работу с устройствами
  и обходила бы защиту (экстренную остановку, исключение своих устройств).
