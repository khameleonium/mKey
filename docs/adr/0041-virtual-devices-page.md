# ADR-0041: Управление виртуальными устройствами в окне и меню значка

- **Статус:** принято (2026-10-08, по просьбе владельца)
- **Связано:** FR-VD-8, FR-VD-4, ADR-0028

## Контекст

Владелец создал «второй геймпад» мастером и не понял, где его искать (в «Устройствах» виртуальные
устройства видны, только пока проект включён), увидел пустой конструктор проекта (раскладка была
только в тексте) и не знал, исчезает ли геймпад при выключении проекта. Нужны одно место со всеми
виртуальными устройствами, понятное состояние и управление.

## Решение

1. **Устройство по-прежнему живёт в проекте** (ADR-0028): включить устройство — включить его
   проект; карточка честно говорит, что ещё в этом проекте включится вместе с ним (`others`).
2. **API:** `GET /devices/virtual` дополнен списком `all` — устройства всех проектов с состоянием
   `on` / `off` / `error`, числом привязок, признаком «прячет клавиши» (`hides`) и `others`;
   `GET /devices/virtual/{name}/state` — нажатые кнопки и положения осей подключённого устройства
   (`contracts.VirtualDeviceManager.State`) для проверки вживую.
3. **Окно:** страница «Виртуальные устройства» (карточки, переключатель, «Новое устройство» для всех
   видов с готовыми раскладками, проверка вживую, удаление «только устройство» или «весь проект»);
   создание и правка — через уже существующие API проектов (импорт, сохранение), без новых записей
   на диск в обход хранилища.
4. **Меню значка:** «Виртуальные устройства» с галочками (включает и выключает проект устройства).
5. **Конструктор проекта:** раздел «Виртуальные устройства и раскладка» вместо пустого места.

## Последствия

- Проверка вживую опрашивает состояние (≈15 раз в секунду, пока открыта): собственные устройства mKey
  не читаются модулем ввода (петля обратной связи, AGENTS §5), поэтому состояние берётся у модуля вывода.

## Альтернативы

- Устройства отдельно от проектов (свой файл) — меняет решение владельца из ADR-0028; отвергнуто.
