# ADR-0044: Токен окна сохраняется между перезапусками mKey

- **Статус:** принято (2026-10-08, по жалобе владельца)
- **Связано:** SEC-5, ADR-0021 (веб-интерфейс)

## Контекст

Окно программы входит по токену из ссылки (`/?t=…`) и дальше работает по cookie. Токен создавался
заново при каждом запуске демона, поэтому после перезапуска mKey открытое окно получало 401 и
показывало «Нет связи… запустите mKey», а обновление страницы не помогало — помогало только
открыть окно заново из меню значка.

## Решение

1. Демон берёт прежний токен из личного каталога времени выполнения (`$XDG_RUNTIME_DIR/mkey/token`),
   если файл обычный, с правами 0600, принадлежит текущему пользователю и содержит токен
   правильного вида (256 бит в hex); иначе создаёт новый. При остановке файл токена не удаляется
   (сокет и сведения о порте — удаляются).
2. Каталог времени выполнения находится в памяти и очищается при перезагрузке компьютера — после
   неё токен новый.
3. Окно отличает «вход устарел» (401) от «mKey не отвечает»: плашка «откройте окно заново: значок в
   трее → «Открыть» или `mkey gui`»; поток событий, закрытый не из-за входа, переподключается сам.

## Последствия

- Токен живёт до перезагрузки компьютера, а не до перезапуска демона. Файл токена доступен только
  владельцу (как и раньше), проверки Host/Origin (SEC-5) не меняются.

## Альтернативы

- Постоянный токен в `~/.config` — жил бы и после перезагрузки; без нужды увеличивает срок жизни
  секрета; отвергнуто.
