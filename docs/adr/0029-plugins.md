# ADR-0029: Плагины — процессы с JSON-RPC 2.0 через stdio, Lua-плагины и плагины-данные

- **Статус:** принято (2026-10-02)
- **Связано:** T9.1–T9.7, FR-PLG-1…9, D13, §4.3 (точки расширения)

## Контекст

mKey должен расширяться сторонними авторами: новые действия, условия, триггеры («HTTP-запрос»,
«вебхук», «MIDI») без правки движка и окна программы (FR-PLG-1). D13 уже выбрало способ:
отдельные процессы с JSON-RPC 2.0 через stdin/stdout (любой язык, падение не роняет демон) плюс
Lua-плагины и плагины-данные; Go `plugin` (.so) не используем. Здесь — подробности протокола,
жизненного цикла, хранения и того, что нужно поменять в ядре.

## Решение

1. **Модуль `plugins`** (`internal/pluginhost`, необязательный) находит плагины в
   `~/.local/share/mkey/plugins/<id>/` и `/usr/share/mkey/plugins/<id>/` (первый важнее),
   читает `plugin.yaml` (FR-PLG-2), запускает **включённые** и регистрирует их виды в обычных
   точках расширения (`action`, `condition`, `trigger`) — для движка, конструктора и проверки
   проектов плагинный вид неотличим от встроенного. Плагин без кода (`kind: data`) приносит
   шаблоны проектов.
2. **Какие плагины включены** — список `modules.plugins.active` в `config.yaml` (решение
   владельца: все настройки — в понятных файлах). Новый плагин выключен, пока человек не
   посмотрит разрешения и не включит его (FR-PLG-4).
3. **Протокол** — JSON-RPC 2.0, одно сообщение на строку (UTF-8, `\n`), stdout — только
   протокол, stderr — журнал плагина (сохраняется в `~/.local/state/mkey/plugins/<id>.log`).
   Методы (полностью — `docs/plugins.md`):
   - mKey → плагин: `initialize`, `shutdown`, `ping`, `action.validate`, `action.run`,
     `condition.validate`, `condition.check`, `trigger.validate`, `trigger.arm`,
     `trigger.disarm`; отмена — уведомление `$/cancelRequest {id}`;
   - плагин → mKey: уведомление `trigger.fire {handle, vars}`; запросы `mkey.send`,
     `mkey.vars.get`, `mkey.vars.set`, `mkey.notify`, `mkey.log`.
   Ответ на `initialize` описывает виды плагина: `id`, имена и описания на языках
   (`name: {ru, en}`), категория, JSON Schema параметров — по ним конструктор строит блоки.
4. **Названия на языках плагина** — в `contracts.ExtensionMeta` добавлены необязательные
   `Names`/`Descriptions` (язык → текст): API берёт их, если у вида нет ключа перевода mKey.
5. **Реестр расширений** получает `Unregister(point, id)`: выключение, падение и обновление
   плагина убирают его виды из палитры. Проект, где используется вид выключенного плагина,
   не включается с понятной ошибкой «вид из плагина X, плагин выключен».
6. **Разрешения** (FR-PLG-5): `output.send`, `vars.read`, `vars.write`, `notify` проверяются
   на каждом запросе плагина к mKey (нет разрешения — ошибка `-32001`). `net`, `exec`,
   `input.*`, `desktop.*` — объявления для человека: процесс работает с правами пользователя,
   mKey не может запретить ему сеть или запуск программ — это честно написано в окне.
7. **Изоляция** (FR-PLG-6): таймауты — `initialize` 5 с, `*.validate` 2 с, `condition.check`
   2 с, `ping` 2 с (раз в 30 с); `action.run` — без таймаута, но отменяется вместе с событием
   (`$/cancelRequest`). Упавший или зависший плагин перезапускается через 1, 2, 4… с; три падения
   за минуту — плагин отключается до следующего включения человеком, приходит уведомление.
   Взведённые триггеры после перезапуска взводятся заново.
8. **Lua-плагины** (`kind: lua`) выполняются в демоне в собственном `LState` модуля `lua`
   (точка `lua_extension` не нужна): `mkey.register_action{...}` и т. п. — T9.3.
9. **Версии:** `plugin_api: 1`; плагин с другой мажорной версией не запускается («нужна версия
   N»). Добавление методов и необязательных полей — без смены версии.

## Последствия

- Плагин на любом языке добавляет действия, условия и триггеры; окно показывает их без правки
  фронтенда; падение плагина не влияет на демон.
- Контракт `ExtensionRegistry` расширен (`Unregister`), `ExtensionMeta` — полями `Names`,
  `Descriptions` (обратно совместимо).
- Плагины не участвуют в горячем пути ввода (FR-PLG-7): триггеры приходят в движок событиями.
- Десктоп-адаптеры и init-системы в плагинах — после фазы 8 (их контракты ещё не
  зафиксированы); точки расширения для них уже есть.

## Альтернативы

- **gRPC / hashicorp go-plugin** — тяжело для плагинов не на Go, нужна генерация кода.
- **Go plugin (.so)** — точное совпадение тулчейна, cgo, падение роняет демон (D13).
- **HTTP-сервер в плагине** — порты, авторизация, сложнее для автора; stdio проще и безопаснее.
