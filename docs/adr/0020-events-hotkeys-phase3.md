# ADR-0020: Решения этапа 3 — проекты, горячие клавиши, перехват, скрипты

- **Статус:** принято
- **Дата:** 2026-09-30
- **Связано:** SPEC §5.2–5.4, §7, §8; T3.1–T3.9

## Контекст

Этап 3 вводит события, горячие клавиши с перехватом клавиатуры и скрипты. Часть решений
в ТЗ не описана или при реализации оказалась иной.

## Решение

1. **Модель проекта открытая** (`internal/lib/project`): триггер и условие — `{type, параметры}`,
   действие — карта с одним ключом `{вид: значение}`. Параметры проверяют сами виды из реестров
   (модули `engine`, `hotkeys`, `script/*`, в будущем плагины). Новый вид не требует правки модели.
2. **`active_when` — список условий** в том же формате, что `conditions` (в SPEC §8 был пример
   с другой формой). Добавлено поле проекта `remaps` (FR-HK-4).
3. **config.yaml** читается один раз при запуске демона (`internal/lib/config`): язык,
   `modules.<id>.enabled` и секции настроек модулей. Горячая перезагрузка — только у проектов.
   JSON Schema файлов перенесена на этап 5 (нужна GUI).
4. **Горячие клавиши — отдельный модуль `hotkeys`**, синхронный обработчик модуля `input`
   (`contracts.InputHandler`): решение «съесть нажатие» принимается прямо в потоке чтения.
   Замер: ~1,3 мкс на событие (NFR-1 требует < 1 мс).
5. **Перехват (grab + passthrough) живёт в модуле `input`**: копия устройства (`mKey passthrough: …`)
   создаётся там же, где открыт файл устройства. Защиты: захват только при отпущенных клавишах;
   экстренная остановка проверяется до обработчиков, снимает перехват и **приостанавливает mKey
   целиком — ни горячие клавиши, ни таймеры, ни другие триггеры не срабатывают до `mkey resume`**
   (исправлено по результатам проверки владельцем: сначала отключался только перехват, и F8 продолжала
   срабатывать в режиме наблюдения);
   watchdog (500 мс) тоже отключает перехват; при снятии захвата зажатое на копии отпускается.
6. **Состояние переключателя (`on: toggle`) ведёт движок**, а не модуль горячих клавиш: после
   `StopAll`/экстренной остановки следующее нажатие снова включает, а не «выключает уже выключенное».
7. **Правило сочетаний:** лишние модификаторы запрещают срабатывание, лишние обычные клавиши — нет.
8. **Действия одного выполнения события делят раннер:** клавиша, зажатая одним действием,
   остаётся зажатой для следующих и отпускается по окончании события (нужно блокам конструктора).
9. **Ограничитель скорости (SEC-4) замедляет, а не отбрасывает** события: потерянное «отпускание»
   оставило бы клавишу зажатой. По умолчанию 2000 событий/с на устройство.
10. **Условия `window`/`pixel`** не зарегистрированы до фазы 8 — проект с ними отвергается с
    понятной ошибкой (и прежняя версия продолжает работать).
11. **`mkey run` запускает события** в форме `проект/событие`; запуск файлов `.lua`/`.sh` без
    события отложен (нет контекста события).
12. **Уведомления рабочего стола** (модуль `desktop`, D-Bus `org.freedesktop.Notifications`):
    экстренная остановка и ошибки в проектах сообщаются пользователю сами.

## Последствия

- Индикаторы CapsLock/NumLock на захваченной клавиатуре могут не обновляться (копия не передаёт
  LED обратно) — ограничение, исправить при необходимости в фазе 10.
- Вывод пользователя из группы `input` при удалении и JSON Schema — позже (фазы 4 и 5).

## Альтернативы

- Встроить горячие клавиши в `engine` — отвергнуто: модуль `engine` не должен знать про evdev.
- Использовать keyd для перехвата — отвергнуто ранее (ADR-0005).
