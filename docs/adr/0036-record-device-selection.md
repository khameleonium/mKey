# ADR-0036: Выбор отдельных устройств для записи

- **Статус:** принято (2026-10-08, по просьбе владельца)
- **Связано:** FR-REC-2, ADR-0024 (запись), ADR-0035

## Контекст

Что записывать, задавалось только классами устройств (`kinds`: клавиатура, мышь, геймпад…). Владелец
записал игру с геймпадом, но геймпад по умолчанию не записывается — запись оказалась пустой без
предупреждения. Просьба: в меню выбора — реальные имена устройств («ID 2dc8:310a 8BitDo Ultimate 2C
Wireless Controller»), категории, отдельная категория «Виртуальные устройства», возможность снять все
галочки и предупреждение о пустой записи.

## Решение

1. **Настройки записи:** `devices` — свой выбор устройства по ключу «VID:PID имя» (одинаков после
   переподключения и перезагрузки) → записывать ли; важнее `kinds`. `kinds` — классы «по умолчанию»
   для устройств без своего выбора (в том числе подключённых позже); может быть пустым.
2. **Виртуальные устройства** (`InputDevice.Virtual`: устройство лежит в /sys/devices/virtual) без
   своего выбора не записываются; собственные устройства mKey (`InputSource.OwnDevices`) показываются
   в той же категории без галочки.
3. **Категории** (`RecordDevice.Category`): keyboards, gamepads (геймпад важнее «клавиатурного»
   интерфейса того же устройства), touch, other, virtual.
4. **API:** `GET /api/v1/recordings/devices` — устройства для выбора; `settings/recording` принимает
   и отдаёт `devices`. Настройки записи сохраняет модуль записи (`contracts.ConfigWriter`), поэтому окно
   и меню значка меняют одно и то же.
5. **Предупреждения:** `RecordingInfo.Devices` при начале записи — выбранные подключённые устройства;
   пусто — окно спрашивает «выбрать или всё равно записать», значок и `mkey rec` предупреждают. Пустая
   запись (0 действий) — предупреждение вместо «сохранена».

## Последствия

- Два одинаковых устройства (тот же VID:PID и имя) выбираются вместе.
- Старые настройки (`kinds`) работают как раньше; `devices` в config.yaml появляется пустым.
