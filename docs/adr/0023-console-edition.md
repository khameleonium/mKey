# ADR-0023: Консольная сборка mkey-cli

- **Статус:** принято
- **Дата:** 2026-09-30
- **Связано:** D16, T5, T6; решение владельца от 2026-09-30

## Контекст

Владелец хочет пользоваться mKey и без окна: запустил терминал, записал ввод, одной командой
повторил. Окно и значок в трее должны быть необязательными. Модули окна уже отключаются
настройками, но в программе остаются встроенные файлы интерфейса, веб-порт и ярлык в меню.

## Решение

- Build-тег `nogui` собирает **консольную версию** (`make build-cli` → `./mkey-cli`); `make build`
  собирает обе версии.
- В консольной версии нет: встроенных файлов окна, модуля `tray`, веб-порта 127.0.0.1:17420
  (API слушает только Unix-сокет для команд терминала), ярлыка и иконки в меню при установке.
  `mkey gui` объясняет, что окна в этой версии нет; `mkey` без аргументов показывает справку.
- Выбор делается в `internal/app/gui.go` / `nogui.go` (список модулей и файлы окна) и
  константой `buildinfo.GUI` (тексты установки, `mkey version`). Остальной код общий: CLI, демон,
  проекты, макросы и запись работают одинаково в обеих версиях.
- `make test` и `make lint` проверяют и консольную сборку (`go vet -tags nogui`, тесты
  `cmd`, `app`, `api`, `setup` с тегом).
- Обе версии устанавливаются как `~/.local/bin/mkey` (устанавливается одна из них).

## Последствия

- Консольная версия меньше (≈11 МБ против ≈14 МБ) и собирается без Node.
- Новые модули окна добавляются в `guiModules()`, а не в общий список.

## Альтернативы

- Отдельная программа с урезанным набором команд — два разных кода, больше работы и расхождений.
- Только отключение модулей в настройках — не убирает веб-порт по умолчанию и ярлык в меню.
