# ADR-0040: «Мышь как руль», «рычаг» и кривая отклика в привязках

- **Статус:** принято (2026-10-08, по просьбе владельца)
- **Связано:** FR-VD-3, FR-VD-6, ADR-0028, ADR-0039

## Контекст

Владелец попросил управлять рулём мышью или стиками геймпада. Привязка «мышь → стик» наклоняет ось по
скорости мыши и возвращает её в центр, когда мышь остановилась: рулём так не порулить — угол нужно
держать. Стиком рулить можно и сейчас, но ему нужна кривая отклика: прямая делает руль «нервным» у центра.

## Решение

Новые настройки привязок (формат проекта, `project.Binding`):

1. **`steer: true`** у «мышь → ось»: движение мыши прибавляется к положению оси (≈1000 единиц мыши —
   от центра до упора при `sensitivity: 1`), ось держит положение, пока мышь стоит.
2. **`recenter_ms`** (только со `steer`, 0…10000): ось сама возвращается в центр со скоростью «из упора
   за recenter_ms», когда мышь не движется; 0 — держит.
3. **`curve`** у «ось → ось» (0.2…5, по умолчанию 1): положение после мёртвой зоны возводится в степень
   с сохранением знака.

4. **`latch: true`** у «кнопка → ось» — «рычаг» (дополнено для РУД лётного джойстика): после
   отпускания ось остаётся там, где была (плавное движение `ramp_ms` останавливается); `value` может
   быть 0 («рычаг в ноль»).

Проверки — в `contracts.CompileBinding` (лишняя настройка — `dsl.binding_option`, вне пределов —
`dsl.binding_range`).

## Последствия

- Старые проекты не меняются: без новых полей поведение прежнее.
- Таймер привязок работает, пока руль движется или возвращается в центр; руль, который держит угол, таймер
  не будит.

## Альтернативы

- Отдельный вид источника «мышь-руль» — то же самое, но непривычнее для тех, кто знает привязки; отвергнуто.
