# ADR-0035: Автотесты окна — Playwright на демоне без настоящих устройств

- **Статус:** принято (2026-10-07)
- **Связано:** T5.10, T12.11, SPEC §14 (открытый вопрос 4), AGENTS.md §5

## Контекст

Окно проверялось вручную и разовыми скриптами. Автотестам нужен настоящий демон, но он не должен
читать и захватывать клавиатуру разработчика и нажимать что-то в живой сессии (AGENTS.md §5),
а в CI нет /dev/uinput. Флаг `mkey daemon --fake-backends` был упомянут в AGENTS.md, но не сделан.

## Решение

1. **`mkey daemon --fake-backends`** (`app.Options.FakeBackends`): модули ввода и вывода заменяются
   вариантами без устройств (`input.NewFake` — пустая временная папка вместо /dev/input, копии
   устройств в памяти; `output.NewFake` — виртуальные устройства в памяти); значок в трее и
   проверка обновлений не подключаются. Всё остальное — настоящее: API, проекты, движок, скрипты.
2. **Playwright** (`@playwright/test`, только devDependency фронтенда): `web/e2e/` —
   `global-setup.ts` запускает собранный `./mkey` с `--fake-backends` во временной «домашней»
   папке (свои настройки, порт 17499), тесты открывают окно по ссылке с токеном. Локально —
   `make e2e` (можно с установленным Chrome: `MKEY_E2E_CHANNEL=chrome`), в CI — задача `e2e`
   (`npx playwright install --with-deps chromium`).

## Последствия

- Новая зависимость разработки: `@playwright/test` (Apache-2.0); в бинарник не попадает.
- Основные сценарии окна (главная, проект из шаблона и сухой прогон, интервалы нажатий, «Скрипты»,
  устройства) проверяются при каждом изменении.
- `--fake-backends` пригоден и для ручных проверок окна на машине разработчика.

## Альтернативы

- puppeteer-core с системным Chrome — нет своего запускателя тестов, отчётов и трассировки.
- Тесты компонентов без демона — не ловят ошибки связки окна и API.
