# ADR-0022: Веб-интерфейс этапа 5 — поток новостей, значок в трее, редактор кода

- **Статус:** принято
- **Дата:** 2026-09-30
- **Связано:** T5.1–T5.10, FR-UI-1…10, FR-INST-2, FR-INST-5, SEC-5, SEC-7

## Контекст

На этапе 5 появляется окно программы (Svelte 5, встроено в бинарник): конструктор событий,
проекты, устройства, диагностика, настройки и мастер первого запуска, а также значок в трее.
Нужно было решить, как окно узнаёт о событиях демона, как ловить нажатие для «Нажмите клавишу…»,
чем показывать YAML и скрипты, как рисовать значок в трее и как окно строит блоки, не зная
конкретных видов действий.

## Решение

1. **Поток новостей — Server-Sent Events** (`GET /api/v1/stream`) вместо WebSocket, указанного
   в T5.1: данные идут только от демона к окну, SSE есть в стандартной библиотеке Go и браузере
   (`EventSource` сам переподключается), дополнительной зависимости не нужно. Команды окно
   отправляет обычными HTTP-запросами.
2. **«Нажмите клавишу…» — запрос `POST /api/v1/capture/key`** (ждёт нажатия, `combo` — сочетание
   до первого отпускания, модификаторы без стороны: `Ctrl+H`) вместо `/ws/input` из T5.7.
3. **Значок в трее — собственная реализация StatusNotifierItem + dbusmenu** (`internal/lib/sni`,
   поверх уже используемой `godbus/dbus`) вместо `fyne.io/systray`: у той библиотеки глобальное
   состояние, она закрывает общее подключение к сессионной шине и пишет в стандартный `log`.
   Модуль `tray` необязательный: без трея (GNOME без AppIndicator) mKey работает как обычно.
4. **Редактор кода — CodeMirror 6** (npm: `codemirror`, `@codemirror/{view,state,language,
   autocomplete,lint,lang-yaml,legacy-modes}`, лицензия MIT). Загружается отдельным файлом
   только при открытии редактора, основной файл интерфейса остаётся небольшим.
5. **Перетаскивание — встроенный HTML5 Drag and Drop** вместо SortableJS: списки блоков
   вложенные, а перенос между ними удобнее делать по uid блока в модели редактора.
6. **Блоки строятся по реестру** (`GET /registry`): API добавляет названия на языке клиента,
   подписи полей (`title`), значений (`x-enum-labels`) и вариантов; схемы видов получили
   подсказки `x-widget`, `x-lang`, `x-advanced` (docs/modules.md). Порядок видов — порядок
   регистрации (раньше — по ID), порядок полей схемы сохраняется.
7. **Перевод «блоки ⇄ текст макроса» — на стороне демона** (`contracts.ActionConverter` в
   модуле engine; `POST /dsl/to_actions`, `POST /actions/to_dsl`): один источник истины для
   действий и DSL; окно не повторяет логику разбора.
8. **Типы API во фронтенде написаны вручную** (`web/src/lib/types.ts`) по `docs/openapi.yaml`,
   а не сгенерированы (отступление от AGENTS.md §6.3): API небольшой, а `openapi.yaml` описывает
   ответы кратко; генератор добавил бы зависимость и не дал бы точных типов. Файлы правятся вместе.
9. **Мастер первого запуска в окне** проверяет доступ к устройствам (кнопка «Выдать доступ» —
   `POST /doctor/fix`), нажатие и печать. Установку программы и автозапуск по-прежнему
   выполняет `mkey setup` (эндпоинтов `/setup/*` нет).
10. **Удаление из окна** (`POST /uninstall`) запускает `mkey uninstall --yes` отдельным
    процессом в своей сессии: он останавливает демон и удаляет файлы по манифесту.

## Последствия

- Новые виды блоков от модулей и плагинов появляются в конструкторе без правок фронтенда.
- Сохранение из конструктора переписывает файл проекта без комментариев (YAML из структуры);
  правка во вкладке «Текст (YAML)» сохраняет файл как есть.
- Playwright e2e (T5.10) и режим `--fake-backends` не сделаны: проверка окна — ручная
  (владелец) и роботом в невидимом браузере на время разработки.

## Альтернативы

- WebSocket (`nhooyr.io/websocket`, `gorilla/websocket`) — лишняя зависимость ради одностороннего потока.
- `fyne.io/systray` — см. п. 3; `getlantern/systray` требует cgo (GTK).
- Monaco Editor — в несколько раз тяжелее CodeMirror.
- `openapi-typescript` — зависимость ради небольшого набора типов.
